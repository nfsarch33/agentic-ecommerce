# v2.0.0 Release Demo Runbook

This runbook gives stakeholders a deterministic local walkthrough of the v2.0.0 release flow. It uses local services and mocks only: no live MiniMax, WooCommerce, Slack, SMTP, cloud, or external webhook calls.

## Scope

The release demo covers:

- storefront browse -> cart -> checkout -> order confirmation
- admin login -> manage order
- AI content workflow start -> Temporal activities complete
- compliance passes
- publish to WooCommerce mocked by the local workflow test environment
- media processed through the MIS path
- n8n webhook delivery through a local/mock receiver

## Backend Evidence

Run these commands from the backend repo or its runx worktree:

```bash
GOTOOLCHAIN=auto GOSUMDB=sum.golang.org go test -count=1 ./internal/workflow ./internal/webhook/outbound ./internal/qa
make release-perf-smoke
```

expected checkpoints:

- `TestProductPublishWorkflowE2EWithRealActivities` completes with status `published`.
- `TestContentGenerationWorkflowApprovesFactCheckedContent` completes with status `approved`.
- `TestMediaProcessingWorkflowSourcesProcessesQALinksAndStores` completes with status `linked`.
- `TestServiceDeliversEventToMatchingRegistrationsAndRecordsResults` records one successful local webhook delivery.
- `make release-perf-smoke` keeps catalog, order creation, AI generation, and Temporal workflow start under the v1.8.0 budgets.

For k6 regression against a local API, run a local receiver on loopback, then point the script at it:

```bash
BASE_URL=http://127.0.0.1:8080 \
WEBHOOK_URL=http://127.0.0.1:18081/n8n/order-placed \
MEDIA_SOURCE_URL=http://127.0.0.1:18081/fixtures/resistance-band.png \
make load-test
```

Expected k6 surfaces:

- `product_catalog` p95 < 100ms
- `order_creation` p95 < 200ms
- `ai_generation_mocked` p95 < 2s
- `temporal_workflow_start` p95 < 500ms
- `media_validation` p95 < 500ms
- `webhook_delivery` p95 < 500ms

## Frontend Demo

Run from the frontend repo or its runx worktree:

```bash
bun install
make release-e2e
```

The Playwright release spec starts the deterministic Bun mock backend from `e2e/run-with-mock.ts`, so the UI can be demonstrated without external services.

Expected screenshots/checkpoints:

- Products page: `Resistance Band Set` is visible and can be added to cart.
- Cart page: cart total is visible and checkout is available.
- Checkout page: the order form accepts deterministic shopper details.
- Order confirmation page: `Order confirmed` and `shopper@example.com` are visible.
- Admin orders page: order management shows the placed order and `Resistance Band Set`.
- AI Description Studio: generated copy is approved and the publish workflow starts.
- Workflow detail: Temporal timeline shows compliance, media validation, human review, and mocked WooCommerce publish completing.
- Compliance dashboard: release-mode compliance shows `Pass` and `96/100`.
- Media library: MIS validation reports `QA passed`.
- Webhooks page: local/mock n8n delivery reports `delivered`.

## Demo Talk Track

1. Shopper browses the storefront, adds the product to cart, and places an order.
2. Operator signs in to admin and confirms the order is visible for fulfilment.
3. Operator opens AI Description Studio, generates deterministic product copy, approves it, and starts the publish workflow.
4. Temporal executes compliance, media validation, review, and mocked WooCommerce publish activities.
5. Compliance passes and the media asset has gone through the MIS validation path.
6. The local/mock n8n receiver records the webhook delivery, proving the event bridge without touching Slack, SMTP, or external webhooks.

## Safety Boundaries

- Use loopback URLs only for webhook and media fixture endpoints.
- Keep `FLEET_AI_BRIDGE_URL`, WooCommerce credentials, cloud credentials, Slack tokens, and SMTP settings unset.
- Do not paste screenshots containing browser profiles, auth tokens, or environment variables into release notes.
